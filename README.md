# 红域小红书直播复盘诊断 Skill

一个基于小红书千帆截图、数据大屏、导出表格与回放证据的直播复盘 Skill。它会先定位漏斗断点，再区分数据事实、诊断判断与待验证假设，最后给出下一场可执行、可衡量的调整方案。

适合小红书直播带货商家、主播、运营和操盘手。默认采用“用户上传资料”的方式工作，不要求 AI 登录商家后台。

## 能做什么

- 复盘单场直播，定位曝光、进房、停留、互动、点击、加购、支付与退款问题；
- 对比多场直播、不同主播或不同时段，识别稳定趋势；
- 结合观看人数、支付金额与新增粉丝曲线，分析成交节奏和关键时间点；
- 排查潜在限流问题，但不会仅凭掉量就武断认定“被限流”；
- 生成下一场直播的动作、负责人、观察指标、验证周期和止损条件。

## 安装

在 Codex 中调用 `$skill-installer`，并提供本仓库地址：

```text
请使用 $skill-installer 从 https://github.com/lfwlw162-collab/hongyu-xhs-live-diagnosis 安装这个 Skill。
```

也可以下载本仓库，将完整目录放入所用客户端的个人 Skills 目录；不同客户端版本的目录位置可能不同，优先使用安装器。

## 怎么使用

安装后，可以直接说：

```text
使用 $hongyu-xhs-live-diagnosis，根据我上传的千帆数据截图，复盘这场小红书直播并给出下一场改进方案。
```

也可以针对具体目标提问：

```text
使用 $hongyu-xhs-live-diagnosis，对比这三场下午场和晚场，判断主要差异来自流量、货盘还是主播承接。
```

```text
使用 $hongyu-xhs-live-diagnosis，排查这场直播突然掉量是否支持“限流”判断，并列出证据和其他可能解释。
```

## 第一次诊断要准备什么

进入小红书千帆后，按以下路径取数：

`左侧菜单栏 → 数据 → 直播场次 → 选择时间 → 找到目标场次 → 数据详情`

建议上传：

1. “数据详情”页面从上到下的全部截图，截图之间保留少量重叠；
2. “查看数据大屏”中的两张综合趋势截图：
   - 观看人数 + 支付金额；
   - 观看人数 + 新增粉丝数。
3. 类目、价格带、主播、是否投流，以及本场目标；
4. 若做深度复盘，再补商品明细、投流数据、退款原因和关键时间点回放。

两张大屏截图都要保留顶部核心指标、选中的曲线图例与完整时间轴。详细规范见 [截图与取数说明](docs/screenshot-guide.md)。

## 输出原则

- 先找漏斗断点，不用 GMV 高低代替诊断；
- 把事实、推断、假设和缺失证据分开；
- 经验阈值只作参考，优先对比同账号、同类目、相近价格带和相近时段；
- 曲线相关性不等于因果，关键节点尽量用回放或运营记录验证；
- “24 条隐形限流规则”属于红域工场实战排查规则，并非小红书官方公开的算法说明；
- 不承诺流量恢复时间，不制造“必中算法”或“百分百起量”的结论。

可先查看一份完全虚构的 [示例复盘报告](docs/example-report.md)。

## 隐私与数据安全

本仓库不包含真实直播间名称、场次 ID、手机号、客户数据、登录凭证、真实经营截图或原始内部 PDF。

Skill 本身是本地指令与知识文件，不包含独立服务器、埋点或主动上传逻辑。你在对话中提交的数据仍由你使用的 AI 产品按照其隐私政策处理。上传前建议遮盖手机号、收货信息、订单号、用户昵称等不影响诊断的字段；不要提交密码、验证码、Cookie、密钥或其他登录凭证。

更多说明见 [隐私说明](docs/privacy.md)。
