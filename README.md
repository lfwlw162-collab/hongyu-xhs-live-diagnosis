# 红域小红书直播复盘诊断 AI（全平台版）

一套面向小红书直播带货商家、主播和运营的 AI 复盘方法。它根据千帆截图、数据大屏、导出表格与回放证据，定位曝光、进房、停留、互动、商品点击、支付、退款、货盘和潜在限流问题，并生成下一场可验证的调整方案。

这个仓库不是只供 Codex 使用：

- **Codex / ChatGPT**：提供原生 `SKILL.md`；
- **DeepSeek、Kimi、豆包、腾讯元宝、通义千问等普通对话产品**：提供通用提示词和单文件知识包；
- **扣子、腾讯元器、阿里云百炼、百度千帆**：提供智能体与知识库配置指南。

各平台的模型、图片识别、知识库召回和上下文能力不同，因此“方法与知识可以通用”，不代表各平台输出会完全一致。本项目也不是上述平台的官方插件。

## 最快使用方式

### 方式一：普通 AI 对话

适用于 DeepSeek、Kimi、豆包、腾讯元宝、通义千问及其他能接收长文本或附件的 AI：

1. 打开并复制 [全平台核心提示词](core/SYSTEM-PROMPT.md)；
2. 把它作为新对话的第一条指令；
3. 上传 [单文件完整知识包](dist/hongyu-xhs-live-diagnosis-all-in-one.md)，或分别上传 `references/` 下的知识文件；
4. 上传千帆数据截图或导出表格；
5. 发送：`请按红域小红书直播复盘方法诊断这场直播。`

完整操作见 [通用对话平台教程](platforms/generic-chat.md)。

### 方式二：Codex / ChatGPT Skill

在 Codex 中调用 `$skill-installer`：

```text
请使用 $skill-installer 从 https://github.com/lfwlw162-collab/hongyu-xhs-live-diagnosis 安装这个 Skill。
```

安装后可直接说：

```text
使用 $hongyu-xhs-live-diagnosis，根据我上传的千帆数据截图，复盘这场小红书直播并给出下一场改进方案。
```

## 能做什么

- 复盘单场直播，定位曝光、进房、停留、互动、点击、加购、支付与退款问题；
- 对比多场直播、不同主播或不同时段，识别稳定趋势；
- 结合观看人数、支付金额与新增粉丝曲线，分析成交节奏；
- 排查潜在限流问题，但不会仅凭掉量就武断认定“被限流”；
- 生成下一场直播的动作、负责人、观察指标、验证周期和止损条件。

## 第一次诊断要准备什么

进入小红书千帆后，按以下路径取数：

`左侧菜单栏 → 数据 → 直播场次 → 选择时间 → 找到目标场次 → 数据详情`

建议上传：

1. “数据详情”页面从上到下的全部截图，截图之间保留少量重叠；
2. “查看数据大屏”中的两张综合趋势截图：
   - 观看人数 + 支付金额；
   - 观看人数 + 新增粉丝数。
3. 类目、价格带、主播、是否投流，以及本场目标；
4. 深度复盘再补商品明细、投流数据、退款原因和关键时间点回放。

两张大屏截图都要保留顶部核心指标、曲线图例与完整时间轴。详细规范见 [截图与取数说明](docs/screenshot-guide.md) 或 [用户数据清单](core/DATA-CHECKLIST.md)。

## 输出原则

- 先找漏斗断点，不用 GMV 高低代替诊断；
- 把数据事实、诊断判断、待验证假设和缺失证据分开；
- 经验阈值只作参考，优先对比同账号、同类目、相近价格带和时段；
- 曲线相关性不等于因果，关键节点尽量用回放或运营记录验证；
- “24 条隐形限流规则”属于红域工场实战排查规则，并非小红书官方公开算法说明；
- 不承诺流量恢复时间，不制造“必中算法”或“百分百起量”的结论。

可先查看一份完全虚构的 [示例复盘报告](docs/example-report.md)。

## 隐私与数据安全

本仓库不包含真实直播间名称、场次 ID、手机号、客户数据、登录凭证、真实经营截图或原始内部 PDF。

提示词和知识文件本身不包含独立服务器、埋点或主动上传逻辑。你在对话中提交的数据仍由所使用的 AI 产品按照其隐私政策处理。上传前建议遮盖手机号、收货信息、订单号、用户昵称等不影响诊断的字段；不要提交密码、验证码、Cookie、密钥或其他登录凭证。

更多说明见 [隐私说明](docs/privacy.md)。
