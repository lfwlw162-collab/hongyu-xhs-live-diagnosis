# 复盘报告结构

根据任务复杂度缩放，不为凑结构输出空章节。

## 一句话结论

直接指出最大问题位于哪个环节，以及最优先要改什么。不要先复述全部数据。

## 资料完整度与口径

- 已获得：列出截图、表格、回放和时间范围。
- 缺失：只列影响结论的关键项。
- 口径提醒：人数/次数、平台转化率、退款归属、自然/付费是否可比。

## 核心漏斗

用紧凑表格展示：曝光 -> 观看 -> 商品曝光 -> 点击 -> 加购（如有）-> 支付 -> 退款/净成交。

每一级标记：正常、偏弱、明显断点或无法判断。经验阈值与账号历史分开写。

## 三个最重要问题

每个问题包含：

1. 现象；
2. 数据证据；
3. 原因判断；
4. 其他可能解释；
5. 证据等级。

## 渠道、时间与货盘

- 哪些渠道贡献量，哪些渠道贡献成交；
- 公域与私域是否失衡；
- 观看、支付金额、涨粉曲线的波峰与空档；
- 高点击低支付、高成交高退款、零成交或引流型 SKU；
- 需要回放验证的具体时间点。

## 潜规则/限流排查

仅在用户怀疑限流或数据异常时输出。列出确认触发、高度疑似、不能排除、暂不支持四档之一，并说明证据。不要为了迎合用户强行认定限流。

## 下一场执行方案

最多五项，按优先级排序。每项写清：

- 改什么；
- 谁执行；
- 在什么阶段执行；
- 观察什么指标；
- 测试几场或多久；
- 达到什么条件保留；
- 什么条件下停止或更换方案。

## 补充资料

如果结论仍受限，只要求一至三项最关键补充资料，并说明补充后能验证什么。
